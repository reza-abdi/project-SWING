# Public surface threat model

## Scope and safety boundary

Project SWING operates IEEE 39 and IEEE 118 **simulations only**. It is not connected to transmission control equipment. A successful API actuation changes an in-memory pandapower model and writes a local event; it must never be described or deployed as real grid control. The main security objective is to prevent unauthorized or unsafe changes to that simulation, protect credentials and local artifacts, and keep public read endpoints available under ordinary load.

The main trust boundaries are the browser to each HTTP API, the AI Agent service to the Digital Twin API, the AI provider, and local model/data files. User prompts, browser payloads, retrieved regulatory text, provider responses, and network responses are untrusted inputs.

## Threats, controls, and residual risks

| Threat | Current control | Evidence and residual risk |
| --- | --- | --- |
| A caller bypasses Agent approval by calling Twin actuation routes directly | Direct Twin actuation endpoints require the administrator role. Agent proposal creation, rejection, and execution require an operator role. Local development permits loopback callers; remote mode uses role tokens. | `modules/security.py`, `tests/security/test_access_control.py`. Remote deployments must configure strong operator/admin tokens and keep the Twin service behind a trusted network boundary. |
| An approval is replayed, applied to another grid, or used after the grid changes | Proposal IDs are scoped to a grid, requests require an idempotency key, and execution rechecks status, topology, capacity, and action validity before mutation. | `modules/ai_agents/proposal_store.py`, `modules/ai_agents/agent_api.py`, `tests/api/test_approval_flow.py`. A time-of-check/time-of-use window can remain between the final validation and the simulation update; keep each operation serialized per grid if multi-worker deployment is introduced. |
| Prompt injection or hostile retrieved text causes an action | The chat route is read-only. Decision outputs pass a strict action schema and bus allowlist; retrieved reference text and chat history are explicitly marked untrusted. Actuation remains behind human approval and independent physics checks. | `tests/agents/test_prompt_security.py`, `tests/security/test_access_control.py`. Model output quality is not a security boundary; the schema and physics checks are. |
| Cross-site requests or a malicious page opens a telemetry socket | Both APIs use an explicit origin allowlist with credentials disabled. The WebSocket endpoint checks the browser Origin before accepting a connection. Remote allowed origins must use HTTPS. | `modules/security.py`, `modules/physics_engine/api.py`. Reverse proxies must terminate TLS, preserve the browser Origin, and expose only configured HTTPS origins. Origin checks complement authentication; they do not replace it. |
| Script injection in model, event, or provider text | Dashboard rendering uses text nodes/textContent for dynamic content, and UI regression tests cover relevant views. API models bound and validate inputs. | `tests/ui/agent.spec.ts`. Review any new DOM rendering sinks and third-party scripts; a compromised dependency or inline script can still execute in the browser origin. |
| A crafted FAISS pickle executes code | Index deserialization is allowed only after checking a trusted manifest hash, source PDF hash, artifact hashes, and private directory permissions. Pickle/model assets are not deserialized by the security audit. | `modules/ai_agents/rag_builder.py`, `tests/rag/test_rag_builder.py`, `scripts/security_audit.py`. The manifest digest must be pinned through a trusted deployment channel; never accept a hash supplied by an untrusted request. |
| Provider keys leak through source, logs, or the browser | Provider calls are server-side and read credentials from environment configuration. The audit scans tracked text for common credential forms and reports file/line only. | `scripts/security_audit.py`, `.env.example`. Rotate credentials after suspected exposure and keep `.env` out of version control. A pattern scan cannot detect every secret format or history-only exposure. |
| Large or repeated requests exhaust CPU, workers, or paid model quota | APIs cap request bodies, limit expensive route rates per client, and bound concurrent proposal/chat/optimizer/contingency work. Chat payload fields also have schema limits. | `modules/security.py`. Limits are in-process and reset on restart; multiple workers multiply capacity and share neither counters nor semaphores. Put a gateway with global quotas in front of horizontally scaled deployments. |
| A dependency or artifact contains a known vulnerability or unsupported executable content | Dependencies are pinned, binary artifacts are allowlisted by type and inspected without deserialization, and CI runs compile/lint/tests. `pip-audit` can check installed dependencies where available. | `.github/workflows/python-ci.yml`, `scripts/security_audit.py`. The current environment lacks `pip-audit`, so advisory status is not yet verified. Pinning alone does not establish that a dependency is safe. |

## Deployment requirements

- Bind services to loopback for local use. For remote access, use TLS at a maintained reverse proxy, set `SWING_AUTH_MODE` to a supported authenticated mode, configure exact HTTPS `SWING_ALLOWED_ORIGINS`, and supply separately generated operator and administrator tokens through a secret manager.
- Do not expose the Digital Twin actuation API directly to the public internet. The administrator credential has broader power than the browser operator credential.
- Keep model, dataset, FAISS, and event database directories private and writable only by the service account. Verify model provenance before replacing any supplied artifact.
- Use a shared gateway or distributed limiter before running multiple API workers. The current in-process quotas are suitable for a single-process deployment only.
- Run the security audit and dependency advisory scan in a network-enabled CI environment. Review new findings before deployment; this repository's static checks are not a penetration test.
